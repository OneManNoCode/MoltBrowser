PDFs were a blind spot. The side-panel chat grounds itself in
`document.body.innerText` of the active tab, which means: open a PDF,
the chat goes silent, you can't ask "what does page 3 say about
revenue."

Today's fix routes PDFs through a different extraction path so the
chat can read them too — no new UI surface, no plugin install, no
upload-to-cloud step.

## How it works

Chromium renders PDFs inside an isolated `<embed>` driven by PDFium.
That `<embed>` has no DOM you can introspect from a content script —
which is why innerText returns nothing useful on a PDF tab.

What PDFium *does* expose is an **accessibility tree**: every glyph
run in the document gets a leaf `AXNode` whose `kName` attribute is
the actual text content. This is the path Chromium itself uses for
"find in PDF" and for screen readers.

We hook into that:

```cpp
if (active->GetContentsMimeType() == pdf::kPDFMimeType) {
  active->RequestAXTreeSnapshot(
      base::BindOnce(&AiChatSidePanelWebView::OnAxTreeCaptured, ...),
      ui::kAXModeWebContentsOnly,
      /*max_nodes=*/50000,
      /*timeout=*/base::TimeDelta(),
      content::WebContents::AXTreeSnapshotPolicy::kAll);
  return;
}
```

When the snapshot lands, we flatten every node's `kName` attribute
into one big string (capped at the same 50 KB the chat uses for web
pages), prefix the title with " (PDF)" so the chat UI can show a
different icon, and feed it through the same `__moltSetTabContext`
contract every other tab uses. The chat doesn't know it's reading a
PDF — it just reads.

## What you get

- Open any PDF: invoices, research papers, contracts, bank statements
- Side panel chip switches to the page-glyph icon: "Chatting with PDF: …"
- Ask anything: *"summarize page 4"*, *"what's the total amount due?"*,
  *"is there a non-compete clause?"*
- The whole thing runs locally. The PDF never leaves your machine.

## What's not in v1

- We only read the text layer. Image-only PDFs (scanned receipts,
  photographed contracts) need OCR. Next iteration: route image-only
  PDFs through the existing `screen_ai` OCR service.
- 50 KB cap is roughly 8–12 pages of dense text. For longer PDFs the
  chat's existing chunk-and-rank pipeline takes over — you still get
  good answers, you just won't see the whole document at once.
- No "jump to source" yet. The AXTree carries node bounding boxes;
  we could highlight the passage we cited.

## Try it

```
git pull
./scripts/build.sh        # incremental, ~1 min
open chromium/src/out/MoltBrowser/MoltBrowser.app
```

Open any `.pdf` URL, click the spark icon to open the side panel,
ask a question.
